## 1. Философия и принципы

### Общая концепция: «Профессиональная простота»

FlowerOS — это **инструмент**, а не витрина. Люди будут проводить в нём по 8+ часов в день. Поэтому дизайн должен быть:

- **Функционально первым**: информация на экране — это данные, а не украшение
- **Энергосберегающим**: ничто не должно раздражать или утомлять глаз
- **Предсказуемым**: пользователь должен понимать, что произойдёт до клика
- **В меру красивым**: не корпоративный Excel, но и не Dribbble-концепт

### Референсы и вдохновение

| Что нравится | Откуда брать |
|---|---|
| Канбан-календарь заказов | Posiflora — структура колонок по дням, цветные статусы |
| Карточки с минимальной информацией | Linear, Notion |
| Топ-навигация + боковая панель | Vercel Dashboard, Railway |
| Типографика и плотность | Retool, Basecamp |
| Общий «белый» тон | Apple, Craft Docs |

### Антипаттерны (что строго запрещено)

- ❌ Фиолетовые градиенты и «AI-эстетика»
- ❌ Плитки с огромными иконками и мелким текстом (Material Design переизбыток)
- ❌ Анимации ради анимаций — только если несут смысл
- ❌ Цветной фон на всю страницу в админке
- ❌ Слишком много теней (neumorphism) — устарело и утомительно
- ❌ Темы «под цветы» — никаких лепестков в качестве UI-элементов

## 2. Дизайн-система

### 2.1 Цветовая палитра

Система строится на **нейтральном основании** с яркими функциональными акцентами.

#### Базовые нейтралы (фоны, поверхности)

```css
--color-bg-canvas:    #F8F8F6;  /* Основной фон — тёплый белый, почти бумажный */
--color-bg-surface:   #FFFFFF;  /* Карточки, модалки, панели */
--color-bg-sunken:    #F1F0ED;  /* Вдавленные поля, sidebar background */
--color-border:       #E5E4E0;  /* Все границы и разделители */
--color-border-hover: #C9C8C4;  /* Hover на границах */
```

> **Почему тёплый белый, а не холодный #FFFFFF?**  
> `#F8F8F6` имеет чуть бежевый подтон — он менее агрессивен для глаз при длительной работе и создаёт ощущение «живого» интерфейса, а не стерильного.

#### Текст

```css
--color-text-primary:   #1A1917;  /* Основной текст — почти чёрный, тёплый */
--color-text-secondary: #6B6A66;  /* Второстепенный: лейблы, подписи */
--color-text-tertiary:  #A09F9B;  /* Плейсхолдеры, disabled */
--color-text-inverse:   #FFFFFF;  /* Текст на тёмном фоне */
```

#### Акцентные цвета (функциональные)

```css
/* Главный Brand-акцент — тёплый зелёный (живые цветы, природа) */
--color-brand:          #3D7A5E;
--color-brand-hover:    #2F6249;
--color-brand-light:    #EAF4EF;  /* Фон для brand-чипов и badge */

/* Статусы заказов — основа канбана */
--color-status-new:         #3B82F6;  /* Синий — Новые */
--color-status-new-bg:      #EFF6FF;
--color-status-assembled:   #10B981;  /* Зелёный — Собранные */
--color-status-assembled-bg:#ECFDF5;
--color-status-courier:     #F59E0B;  /* Жёлтый — У курьера */
--color-status-courier-bg:  #FFFBEB;
--color-status-done:        #6B7280;  /* Серый — Завершённые */
--color-status-done-bg:     #F9FAFB;
--color-status-return:      #EF4444;  /* Красный — Возврат */
--color-status-return-bg:   #FEF2F2;

/* Системные состояния */
--color-success:  #10B981;
--color-warning:  #F59E0B;
--color-error:    #EF4444;
--color-info:     #3B82F6;
```

#### Почему именно этот зелёный?

`#3D7A5E` — это насыщенный «бутылочный» зелёный. Он:
- Ассоциируется с растениями без китча
- Хорошо смотрится на белом и тёплом фоне
- Достаточно тёмный для AA-доступности при белом тексте
- Не «кричит» и не конкурирует со статусными цветами


### 2.2 Типографика

```
Шрифтовая пара:
  Заголовки: "Geologica" (Google Fonts) — геометрический, современный, не Inter
  Тело текста: "Golos Text" (Google Fonts) — читаемый, кириллица отличная
  Mono: "JetBrains Mono" — для ID заказов, кодов, артикулов
```

**Почему Geologica + Golos Text?**
- Оба шрифта имеют отличную кириллицу — критично для русского UI
- Golos Text разработан специально для экранов, очень читаем при мелких размерах
- Geologica красиво смотрится в заголовках панелей и модалок
- Это не Inter — система будет иметь свою идентичность

#### Шкала размеров (rem)

```css
--text-xs:   0.75rem;   /* 12px — метки, timestamp */
--text-sm:   0.875rem;  /* 14px — основной текст карточек */
--text-base: 1rem;      /* 16px — body, инпуты */
--text-lg:   1.125rem;  /* 18px — подзаголовки */
--text-xl:   1.25rem;   /* 20px — заголовки панелей */
--text-2xl:  1.5rem;    /* 24px — заголовки страниц */
--text-3xl:  1.875rem;  /* 30px — Hero-числа в дашборде */
```

### 2.3 Пространство и сетка

```css
/* Базовый шаг: 4px */
--space-1:  4px;
--space-2:  8px;
--space-3:  12px;
--space-4:  16px;
--space-5:  20px;
--space-6:  24px;
--space-8:  32px;
--space-10: 40px;
--space-12: 48px;

/* Радиусы скругления */
--radius-sm:   4px;   /* Badges, теги */
--radius-md:   8px;   /* Карточки, инпуты */
--radius-lg:   12px;  /* Модальные окна */
--radius-xl:   16px;  /* Боковые панели */

/* Тени */
--shadow-sm:  0 1px 2px rgba(0,0,0,0.06);
--shadow-md:  0 4px 8px rgba(0,0,0,0.08);
--shadow-lg:  0 8px 24px rgba(0,0,0,0.10);
```

### 2.4 Иконки

Используем **Lucide React** (уже в стеке). Размеры:
- 16px — внутри инпутов, в таблицах
- 20px — в кнопках, карточках (стандарт)
- 24px — в навигации, заголовках

Правило: иконки **только поддерживают** текст, никогда не заменяют его без тултипа.

## 3. Архитектура фронтенда

### Структура монорепо (frontend/)

```
frontend/
├── packages/
│   ├── ui/                  ← Общая библиотека компонентов (shadcn/ui + кастом)
│   │   ├── components/
│   │   ├── hooks/
│   │   └── styles/          ← Tailwind config, CSS Variables, fonts
│   └── shared/              ← Types, API-клиент, утилиты (общие для всех порталов)
│       ├── api/             ← TanStack Query hooks + axios-клиент
│       ├── types/           ← Общие TypeScript-типы (OrderStatus, Role, etc.)
│       └── utils/
│
├── apps/
│   ├── admin/               ← Portal A: Owner + Admin + Staff
│   │   ├── src/
│   │   │   ├── features/    ← Feature-Sliced Design (orders/, catalog/, etc.)
│   │   │   ├── layouts/
│   │   │   ├── pages/
│   │   │   └── router.tsx
│   │   └── vite.config.ts
│   │
│   ├── florist/             ← Portal B: Florist (мобильный-первый)
│   │   └── src/
│   │
│   └── customer/            ← Portal C: B2C личный кабинет
│       └── src/
│
└── package.json             ← pnpm workspaces
```

### Стейт-менеджмент

| Тип данных | Инструмент |
|---|---|
| Серверные данные (заказы, склад, клиенты) | TanStack Query (кеш, инвалидация, загрузка) |
| UI-состояние (открыта/закрыта панель, фильтры) | Zustand |
| Формы | React Hook Form + Zod |
| Real-time обновления | SSE через TanStack Query + `refetchInterval` |

### Роутинг и права доступа

```
/auth/login              → публичный
/auth/register           → публичный

/admin/*                 → OWNER, ADMIN
/admin/dashboard         → сводный дашборд

/florist/*               → FLORIST, CASHIER
/florist/orders          → мои заказы на сборку (канбан-упрощённый)
/florist/inventory       → просмотр склада, списание

/courier/*               → COURIER
/courier/deliveries      → мои доставки сегодня

/account/*               → CUSTOMER
/account/orders          → история заказов
/account/loyalty         → баллы, кешбэк
/account/profile         → настройки профиля
```

### 4.1 Portal A — Admin/Owner (Управляющий)

**Пользователи:** OWNER, ADMIN  
**Устройства:** Desktop в первую очередь (1280px+), tablet поддержка

#### Общий Layout

```
┌─────────────────────────────────────────────────────────┐
│  [🌸 FlowerOS]  Поиск...         [🔔] [Аватар ▾]        │  ← TopBar (56px)
├──────────┬──────────────────────────────────────────────┤
│          │                                               │
│  Sidebar │           Main Content Area                  │
│  (220px) │                                              │
│          │                                              │
│ Дашборд  │                                              │
│ Заказы   │                                              │
│ Каталог  │                                              │
│ Склад    │                                              │
│ Клиенты  │                                              │
│ Сотрудн. │                                              │
│ Финансы  │                                              │
│ Аналит.  │                                              │
│          │                                              │
└──────────┴──────────────────────────────────────────────┘
```

**Sidebar детали:**
- Фон `--color-bg-sunken` (`#F1F0ED`) — чуть темнее основного
- Ширина 220px, коллапсируется в 64px (только иконки) по кнопке
- Активный пункт: полоска brand-цвета слева + чуть более тёмный фон
- Секции: разделитель с текстовым лейблом («Операции», «Управление», «Аналитика»)

**TopBar детали:**
- Фон `#FFFFFF`, тонкая нижняя граница `--color-border`
- Глобальный поиск (⌘K / Ctrl+K) — модалка по всему приложению
- Нотификации — слайдинг-панель справа

#### Страница «Дашборд» (главная OWNER)

Главная цель — дать владельцу «пульс бизнеса» за 5 секунд.

```
┌────────────────────────────────────────────────────────┐
│  Сегодня, 19 апреля  •  Суббота                        │
│                                                         │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │Заказов   │ │Выручка   │ │Средний   │ │Остаток   │  │
│  │сегодня   │ │сегодня   │ │чек       │ │на складе │  │
│  │  24      │ │ 47 850 ₽ │ │  1 994 ₽ │ │ 312 ед   │  │
│  │↑12% вчера│ │↑8% вчера │ │          │ │⚠ 3 на 0  │  │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘  │
│                                                         │
│  ┌────────────────────────┐  ┌─────────────────────┐   │
│  │  Выручка за неделю     │  │  Заказы по статусам  │  │
│  │  [Recharts LineChart]  │  │  [Recharts DonutChart]│  │
│  └────────────────────────┘  └─────────────────────┘   │
│                                                         │
│  ┌──────────────────────────────────────────────────┐  │
│  │  Заказы сейчас (мини-канбан, только сегодня)     │  │
│  │  Новые(5)  │  Собранные(8)  │  У курьера(6)      │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

#### Страница «Заказы» — Главный экран

Это **сердце системы** — та самая Канбан-доска из скриншота Posiflora.

**Верхняя панель:**
```
[Календарь заказов]  [🔍 Поиск...]  [📅 Декабрь ▾]  [⚡ Фильтр]  [+ Новый заказ]
```

**Переключатель вида:**
- **Канбан / Колонки** (по умолчанию) — как на скриншоте
- **Список** — таблица для быстрого скана
- **Календарь** — неделя/месяц, заказы как события

**Канбан-доска:**

Колонки соответствуют статусам:

| Колонка | Цвет заголовка | Описание |
|---|---|---|
| Новые | `#3B82F6` синий | Только что созданные, ждут флориста |
| Собранные | `#10B981` зелёный | Флорист завершил, ждут курьера |
| У курьера | `#F59E0B` жёлтый | В доставке |
| Завершённые | `#6B7280` серый | Выполнены сегодня |

**Карточка заказа** (повторяет логику Posiflora но чище):
```
┌─────────────────────────────────────┐
│ 10:00 🚚                     [🛒]   │  ← время + тип + действие
│ Дмитрий Р.                          │  ← имя клиента
│ +7-921-12-**-**                     │  ← маскированный телефон
│ 6 500 ₽                             │  ← сумма
│ №aaar20000018                       │  ← номер заказа (mono font)
│                                     │
│ 👩 ТАТЬЯНА К.   🚴 ТЕМЕРЕНКО Ю.    │  ← флорист + курьер
└─────────────────────────────────────┘
```

Справа от карточки — иконка-действие (зависит от статуса):
- Новые: 🛒 «Взять в работу»
- Собранные: 💰 «Оплатить»
- У курьера: ↩ «Возврат»
- Завершённые: % «Скидка постфактум»

**Строки дат над колонками:**
```
● Чт, 16   ● Пт, 17   ● Сб, 18  [Вс, 19]  ● Пн, 20  ● Вт, 21  ● Ср, 22
```
Текущий день выделен подчёркиванием или фоновым pill-ом.

#### Страница «Склад» (Inventory)

- Таблица с партиями (batch), колонки: Артикул, Название, Количество, WAC-цена, Партия, Срок годности
- Строки с истекающим сроком (≤ 3 дня) — жёлтый фон `#FFFBEB`
- Строки с нулевым остатком — серые, текст `--color-text-tertiary`
- Панель фильтров: по категории, поставщику, состоянию (в наличии / заканчивается / закончилось)
- Кнопка «Списание» → модалка с выбором товара и причины

#### Страница «Финансы»

- Верхние плашки: Выручка / Расходы / Прибыль (за период)
- Recharts AreaChart — выручка vs расходы по дням/неделям/месяцам
- Таблица транзакций с возможностью экспорта в Excel

```
│  • Роза × 25 ...  14 апр  4 850 ₽  │
│  • Тюльпаны × 15  10 апр  2 100 ₽  │
└─────────────────────────────────────┘
```

#### Страница «Баллы и кешбэк»

- Большое число с балансом баллов (красиво, с анимацией счётчика при загрузке)
- Progress bar до следующего уровня лояльности
- История начислений/списаний в виде timeline

## 5. Компонентная библиотека

Используем **shadcn/ui** как основу — он не «устанавливается», а копируется в проект, что даёт полный контроль. Tailwind CSS для утилитарных классов.

### Ключевые компоненты (план реализации)

| Компонент | Откуда | Кастомизация |
|---|---|---|
| `Button` | shadcn/ui | Варианты: `brand`, `ghost`, `destructive` + размеры `sm/md/lg` |
| `Input`, `Textarea` | shadcn/ui | Тёплая граница, focus-ring brand-цвета |
| `Badge` / `StatusChip` | Кастомный | Цвета статусов заказов (New/Assembled/etc.) |
| `Card` | shadcn/ui | Без тени по умолчанию, тонкая граница |
| `DataTable` | TanStack Table + shadcn | Сортировка, фильтры, пагинация |
| `KanbanBoard` | @hello-pangea/dnd + кастомный | Колонки заказов с drag-n-drop |
| `DateRangePicker` | shadcn/ui Calendar | Выбор периода для фильтров |
| `Combobox` | shadcn/ui | Поиск по клиентам, товарам |
| `Modal` / `Sheet` | shadcn/ui Dialog/Sheet | Sheet для боковых панелей деталей |
| `Toast` | react-hot-toast | Позиция top-right, стиль под дизайн-систему |
| `AreaChart`, `LineChart`, `DonutChart` | Recharts | Обёртки с нашими цветами |
| `Skeleton` | shadcn/ui | Для всех состояний загрузки |
| `Avatar` | shadcn/ui | Инициалы для флористов/сотрудников |

### Правила компонентов

1. **Каждый компонент** принимает `className` для дополнительной кастомизации
2. **Нет жёстких размеров** в пикселях внутри компонентов — только через переменные
3. **Loading state** есть у каждого компонента, работающего с данными (Skeleton/Spinner)
4. **Error state** есть у каждой страницы/блока данных
5. **Empty state** — всегда с иллюстрацией/текстом, без пустого белого экрана

## 6. Поведение и UX-паттерны

### Оптимистичные обновления
При изменении статуса заказа — UI обновляется мгновенно, запрос идёт в фоне. При ошибке — откат и toast с объяснением.

### Real-time
SSE-стриминг для канбан-доски: если флорист обновил статус — у остальных открытых вкладок карточка переезжает автоматически (без перезагрузки страницы).

### Горячие клавиши (admin-панель)
- `⌘K` / `Ctrl+K` — глобальный поиск
- `N` — новый заказ (на странице заказов)
- `←` / `→` — переключение дней в канбане
- `Esc` — закрыть модалку / панель

### Пагинация vs Infinite Scroll
- Таблицы (склад, клиенты, транзакции): **пагинация** с выбором размера страницы (25/50/100)
- Канбан-карточки: **lazy load** при скролле вниз в колонке (если > 20 карточек)

### Подтверждения опасных действий
- Удаление / отмена заказа → AlertDialog с текстом последствий
- Никаких скрытых необратимых действий

### Пустые состояния (Empty States)
```
📭 Нет заказов на сегодня

Создайте первый заказ или подождите новых поступлений.
[+ Создать заказ]
```

## 7. Адаптивность и PWA

### Брейкпоинты

```
sm:   640px   → мобиль landscape
md:   768px   → планшет (florist portal)
lg:   1024px  → laptop
xl:   1280px  → desktop (основной для admin)
2xl:  1536px  → широкий экран
```

### PWA-функциональность

| Фича | Приложение | Статус |
|---|---|---|
| «Добавить на рабочий стол» | Все три | Обязательно |
| Offline-страница | Admin | Показывает кешированные данные |
| Push-уведомления | Florist | «Новый заказ назначен тебе» |
| Offline-функционал | Florist | Можно видеть назначенные заказы без интернета |

### Адаптивное поведение admin-панели

| Ширина | Sidebar | Контент |
|---|---|---|
| > 1280px | Полный (220px) | Полный |
| 1024–1280px | Иконки (64px) | Полный |
| 768–1024px | Скрыт, открывается по бургеру | Адаптирован |
| < 768px | Bottom Tab Bar | Мобильный layout |

## 9. С чего начать

Конкретный порядок первых шагов:

### Шаг 1 — Создай репо и настрой основу (день 1)

```bash
# В корне frontend/
pnpm init
# Создай apps/admin с Vite + React + TypeScript
pnpm create vite apps/admin --template react-ts
cd apps/admin
pnpm add tailwindcss @tailwindcss/vite
pnpm add lucide-react
npx shadcn@latest init
```

При инициализации shadcn выбери:
- Style: Default
- Base color: **Neutral** (мы перепишем под свои CSS vars)
- CSS variables: **Yes**

### Шаг 2 — Пропиши дизайн-систему (день 1–2)

В `src/styles/globals.css` пропиши все CSS-переменные из раздела 2 этого манифеста. Это займёт 30 минут, но сэкономит недели исправлений потом.

### Шаг 3 — Сделай страницу логина (день 2–3)

Это первая страница, которую увидит пользователь. Она должна быть:
- Центрированная карточка на тёплом фоне
- Логотип + «FlowerOS» сверху
- Email + Password + кнопка «Войти»
- Обработка ошибок (неверный пароль → красный текст под полем, не toast)

### Шаг 4 — Layout + базовый Sidebar (день 3–4)

Сделай каркас: TopBar + Sidebar + пустая область контента. Это будет обёртка для всех остальных страниц. Протестируй коллапс sidebar-а.

### Шаг 5 — Канбан заказов (неделя 2)

Это самая важная страница. Начни без drag-n-drop — просто статичные колонки с карточками, получаемыми через TanStack Query. Это даст реальные данные в UI как можно быстрее.

## 📌 Важные решения, принятые в этом манифесте

| Решение | Обоснование |
|---|---|
| Три отдельных приложения (apps/), а не одно с ролевым роутингом | Изоляция кода, разные bundle-ы, разный UX на уровне архитектуры |
| Тёплый белый `#F8F8F6` вместо чистого белого | Комфорт при длительной работе, живой характер |
| Geologica + Golos Text вместо Inter | Идентичность + отличная кириллица |
| shadcn/ui как основа | Полный контроль кода, нет vendor lock-in, легко кастомизируется |
| pnpm workspaces | Переиспользование компонентов между порталами без дублирования |
| TanStack Query для сервера + Zustand для UI | Чёткое разделение ответственности стейта |
